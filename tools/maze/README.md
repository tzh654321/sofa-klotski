# 迷宫难度（maze-3）与迭代生成器

> 2026-11-21。口径来自用户口述的公式 + 两轮「逻辑问题」修正。代码只有这一份：`tools/maze/difficulty.js`
> （Node 里 `require`，浏览器里 `window.MazeDiff`，预览页 `回型迷宫.html` 用的就是它）。
> **改了公式要同时改 `test/maze-difficulty.test.js` 里的手算样例与排序断言。**

## 一、公式

```
迷宫难度  = power mean(-P) of {D_path}      P = 2
            = ( Σ_paths D_path^-P )^(-1/P)
通关路径   = 起点到终点的简单路径（每一格最多踩一次）
D_path    = ( 1 + Σ岔路分 / 100 ) × ( 主路项 )
主路项     = Σ√(被"够格岔路"分开的每一段长度) + 转弯次数
岔路分     = Σ 二层岔路分 ；若这条岔路里再没有岔路 → 死路核(长度, 转弯)
死路核     = 100 · ( l²/(l²+40²) + 0.15·t )
```

## 一·补、2026-11-21 第三轮：多层深度偏好 + 重复计分归一化

| 改动 | 公式 | 为什么 |
|---|---|---|
| 多层深度偏好 | `deadEndScore × depthW(L)`，`depthW(L) = 1 + 0.25·(L-1)` | 光"允许嵌套"（MAX_LEVEL 大）不够，还要让**嵌套比同长度的平铺死路更值钱**，否则搜索没动力长"岔路中的岔路"。第 1 层权重仍是 1，所有已锁定的手算样例不变 |
| 递归上限 | `MAX_LEVEL = 6`（`evaluate(m,{maxLevel})` 可覆盖） | 一到六层岔路都算；第七层按死路截断 |
| 重复计分归一化 | `branchSum × min(1, OFF/CNT)` | 树状盘面 `CNT == OFF`（每格只算一次）→ 系数 1，分数完全不变；环路/密铺盘面同一批格子会在 1~6 层被反复计入，`CNT` 虚高几倍 → 折算回来 |

> 没有第三条的话，深底图（斜纹/棋盘）的分数会虚高一个量级：同一批格子被 6 层递归各算一遍。
> 归一化是"深度偏好"能用的前提。

## 二、三轮修正（每一轮都对应一条用户点名的性质，测试里都有断言）

### 1. 多通路合成：从 1/Σ(1/D) 改成 power mean(P=2)

| 输入 | P=1（老） | P=2（新） | 想要的 |
|---|---|---|---|
| 易(1) + 难(100) | 0.99 | **1.0000** | ≈易 ✓ |
| 易 + 易 | 0.5 | **0.707** | 更易 ✓ |
| 难 + 难 | 50 | **70.7** | 没那么难（不是砍半）✓ |

P=1 还有一个致命问题：路径条数一多就线性摊薄（20 万条 → 分/20 万 → 全变 0.1）。
P=2 时同样的 20 万条只除 √20 万 ≈ 447。`evaluate(m, {p: 1})` 可切回老口径对比。

### 2. 死路核：从 √l 改成「凸起 + 饱和」的 l²/(l²+40²)

老口径 `√l` 是**凹**的：20 条 5 格死路（20·√5 ≈ 44.7）反而比 1 条 100 格（10）分高，
正好和「大量过短 < 少量极长」相反。换成 `l²/(l²+40²)`：

- 短段起步极慢（5 格 ≈ 0.015，近乎噪音）；
- 长段封顶（40 格 ≈ 0.5，100 格 ≈ 0.86，再长也不会无限加分）；
- 于是同样 100 格岔路：**20×5 ≈ 0.31 < 1×100 ≈ 0.86 < 4×25 ≈ 1.12** ✓

二层岔路用同一个核（岔路分 = 若干死路核之和），排序自然继承。

### 3. 岔路加成改成 (1 + Σ/100) × 主路项

老写法 `(Σ岔路分) × (主路项)` 不单调：一条**没有岔路**的走廊得 0 分，加一条最小死路反而更低。
改成从 1 起乘：没有岔路 = 纯主路分，加死路只会往上走，一条走满饱和长度的死路正好把主路分翻倍。

### 4. 主路项加了两条约束

- **BRANCH_EPS = 5**：岔路分低于 5（≈9 格死路）的**不当作分割点**，不切主路。
  否则 20 个 5 格死路会把主路切成 21 段，`Σ√段` 从 √40 涨到 21，凭空多出 3 倍分。
- `seg:'split'`（默认，原口径：按段开方）／`seg:'total'`（整条开方）。
  两者在上面三种岔路排布下同序，`split` 只是量级更大。

## 三、边界情况（规格没写死、这里定下来的）

| 情况 | 处理 |
|---|---|
| 岔路接回主路（环 / 捷径） | 主路格子对岔路是墙，这条岔路断在那儿，按"无岔路的死路"记核分 |
| 岔路内部成环 / 两条岔路重叠 | 每条岔路各自标记、算完撤销（mark/undo），重叠格子两边各算一次 |
| 一条通关路径都没有 | 难度 0（`goal` 不可达时） |

**兄弟岔路必须互不影响**：早期版本用「全局访问戳」贪心消费格子，旋转 90° 后邻居枚举顺序一变，
19×19 密林穿行就从 174.36 变成 171.77（差 1.5%）。改完 6 种等价变换的差 ≤ 1e-13。

## 四、等价局面验证（`node test/maze-difficulty.test.js`，29 条）

- 手算：直走廊 = √2；+1 格死路 = (1+0.0625/100)·√2（必须比纯直廊大）。
- 岔路排序：20×5 < 1×100 < 4×25（整关分与岔路分两种口径都验）。
- 多通路：易+难 ≈ 易、易+易 更易、难+难 ∈ (一半, 原值)。
- 19×19 密林穿行：rot90/180/270、flipX/Y、transpose 六种变换分数完全一致（62.720863）。
- 生成器：预算单调不增、网格→块→网格往返、完美迷宫只有 1 条路径。

> 分数默认要求**穷举**（`exact:true`）。路径数超过 `maxPaths`（默认 20 万）会截断，
> 截断后 DFS 只走了一部分 → **不再保证等价局面同分**。对外发布分数只认 `exact`。

## 五、迭代生成器

```bash
node tools/maze/evolve.cjs --w 31 --h 31 --iters 60 --seed 7     # 回型底图（默认）
node tools/maze/evolve.cjs --base perfect --w 21 --h 21          # 标准完美迷宫底图
node tools/maze/evolve.cjs --from levels/迷宫/01_密林穿行.json     # 从现有迷宫起步
```

- **每次迭代减小改动块数**：第 i 次最多翻 `k = max(1, round(K0·(1-i/iters)))` 格，`K0 = 宽×高/40`。
- **全连通约束**：每次改格之后要求**所有通路格都能从起点走到**（`allReachable`），不只看起点→终点。
  只查起点→终点时，补一格墙就能把整片区域封死，那片区既不计分也不参与岔路 ——
  实测 31×31 有一版 468 个开放格里 **215 个不可达**（46% 的棋盘白扔）。
- **结构算子（这一轮的关键）**。充分利用一条性质：**开洞只会把新格子接进已有通路，永远不会切死已有通路**；
  只有补墙才可能切出一片不可达。于是：
  - `carveSpur`（`--spur 0.55`）：从死路口（40%）/ 走廊格（40%）/ 任意通路格往外挖 1~14 格。
    **不需要连通性检查，命中率 100%**，而后期单格随机翻墙一大半都被 `allReachable` 否掉。
    挖到尽头就是死路（评分最奖励的形状）；挖到半路撞上已有通路就成环（`--loop 0.12`）。
  - `sealTip`（`--seal 0.12`）：封掉一条死路口（端点单格，天然安全），用来回收没价值的短岔路。
  - 停滞 `--patience 40`：连续 40 轮没进步就从最好局面「踢一脚」（挖一条长支路 + 几格翻动）。
- **每轮多个晋级名额（束搜索）**：`--beam B --cand N`，每个名额每轮生 N 个候选、一起评估、保留前 B 个。
  `--beam 1 --cand 1` 就是原来的单点爬山。
- **束里必须留一个「可穷举」名额（精英）**。这一条是踩坑换来的：
  被节点上限截断的评分是**虚高的赝品**（DFS 停在中途 → 只数到几条路 → 分数被抬一个量级），
  搜索会一路追着赝品跑。实测 400 轮那次，beam 里全是「9121 分」的赝品，
  最后能交出去的盘面只有 **59.9 分**（它自己确实是 2 条路、59.9 分）。
  现在：① beam 至少保留一个 `exact` 状态；② 一旦手上有可穷举的好解，截断候选的 fit 直接打 -1。
- **评估提速：反向可达剪枝**（`difficulty.js`）。枚举前先做一次「能不能到终点」的反向 BFS，
  到不了终点的格子一律不枚举。**分数完全不变**，但把「一片环路 + 一条唯一解」的盘面
  （不贡献任何通关路径，却被逐条枚举）从指数级压到线性级 —— 那一版只有 1 条简单路径，却要吃 200 万节点。
- 底图六种（`--base`）：`ring`（回型同心环，默认）/ `perfect`（标准完美迷宫）/ `vstripe`（竖条纹）/
  `dstripe`（斜条纹）/ `checker`（棋盘格）/ `noise`（噪声）。后四种天生不连通（棋盘格的对角邻居在 4 连通下不算邻居），
  统一走 `repair()`：先一步能接上的用 `connectStray`，接不上的用 `bridgeStray`（全格 BFS 到最近主路，沿途开墙）。
- **终点必须是叶子**（`goalIsLeaf`）。否则「终点背后」还能挂一大片区域，而 DFS 一踩到终点就收工，
  那片区域既不计分、也不参与岔路 —— 实测 31×31 斜纹有一版 643 个开放格里 500 多个在终点背后，
  分数只算了 100 多格却报到 14101。叶子不是割点，去掉它剩下的一定还连通，所以这条约束不会误伤连通性。
- **输出目录**：默认 `levels/lab/`（关卡集名就叫 `lab`，会被 `build-levelpacks.js` 打包进页面，
  和正式集并列显示）。文件名 `NN_迷宫 WxH 底图 #seed.json`：`--nn 01` 是第一批（回型），
  新批次用 `--nn 02`、`03`… **只追加，不覆盖已有文件**。不想入库就 `--out D:/tmp/xxx`。
- 大棋盘用 `--maxpaths 40000 --maxnodes 5e5` 做粗筛（收尾那次仍用默认上限复核）。

## 六、可达性：硬约束 vs 软奖励（2026-11-21 实验）

`--reach hard`（默认）每次改格都要求**全部通路格可达**；`--reach soft` 允许临时封死，
改成 `fit = 分数 × (可达/开放)^reachpow`，并给一个**定向修复算子**（`--repair P`）：
随机挑一格不可达的通路格，把它旁边连着主路的墙打开。

21×21 回型底图、6000 次演算、beam6/cand4、seed 1：

| 配置 | 难度 | 不可达 | 死路 | 最深岔路层 |
|---|---|---|---|---|
| soft，无修复算子 | 97.8 | **32 / 211（15%）** | 31 | 1 |
| soft，repair 0.35 / pow 2 | 357.6 | 9 / 224 | 58 | 4 |
| **soft，repair 0.6 / pow 3** | **438.3** | **1 / 234（0.4%）** | 62 | 4 |
| soft，repair 0.8 / pow 4（12000 次） | 619.6 | 3 / 229 | 62 | 4 |
| hard（同预算对照） | 123.4 | 0 | 14 | 2 |

结论：
- **光把约束改成软奖励不行**：随机开洞撞不到"接回主路"的那一格，搜索停在 84% 可达、只有一层岔路。
- **加一个定向修复算子之后**，不可达能压到 0.4%~1.3%，而且难度是硬约束版本的 3~5 倍 ——
  因为它允许"先封死一片、再从别处开口"这种硬约束下被禁掉的重组步，反而search得到更复杂的结构。
- 但**软奖励保证不了 0**：罚 4 次方、12000 次演算仍有 3 格不可达。要严格 0 只能用硬约束。

### 顺带修掉一个致命 bug：岔路递归会重复计分

不封顶时，环让同一批格子从不同入口被反复计入（"兄弟岔路互不影响"必须如此），
搜索 80 轮就能把分数刷到 **767 万** —— 涨的全是重复计数。
现在 `MAX_LEVEL = 4`：一层到四层岔路都算，第五层按死路截断。递归上限是全局固定值，
旋转/镜像不变，等价局面照样同分（测试里 6 种变换仍然一致）。
